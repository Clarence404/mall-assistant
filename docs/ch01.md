# 第 1 章 接入模型与流式对话

起点标签 `ch01-start`，参考答案 `ch01-done`。

## 目标

做出一个能用的最小客服：

- 用 Spring AI 的 `ChatClient` 接入大模型，带上「示例商城客服」的系统提示词（人设）
- 默认接本机 Ollama，换成任意 OpenAI 兼容接口只改 profile，不改代码
- 两个接口：`POST /api/chat` 一次返回完整回答；`POST /api/chat/stream` 用 SSE 一段一段推给页面
- 模型挂了、超时了，给用户一句人话：阻塞接口返回 503 + ProblemDetail，流式接口推一个 `error` 事件后结束，不暴露堆栈

聊天页面 `src/main/resources/static/index.html` 已经写好，这章只写后端。

## 分级提示

先自己试；卡住超过 15 分钟再往下看一级。

### 提示一：思路

1. `ChatClient.Builder` 是 Spring AI 自动配置好的，背后的 `ChatModel` 由 `spring.ai.model.chat` 决定。在 Builder 上设置「默认系统消息」，之后每次 `prompt()` 都会自动带上它
2. 超时类异常可能被包了好几层（`ResourceAccessException` 包着 `SocketTimeoutException`），要沿 `getCause()` 一层层找；找不到超时的，一律算「不可用」。已经是 `ModelCallException` 的别再包一层
3. 阻塞调用：`prompt → user → call → content`，整个包在 try/catch 里
4. 流式调用：`stream()` 得到 `Flux<String>`；Reactor 有现成的操作符做「多久没有新元素就报错」和「把错误换成另一个异常」
5. `@RestControllerAdvice` + `@ExceptionHandler`，返回 `ProblemDetail`；需要加响应头时返回 `ResponseEntity<ProblemDetail>`
6. Controller 返回 `Flux<ServerSentEvent<Object>>`，Spring MVC 会逐条写出 SSE。正常结束后「再拼一个」done 事件；出错时「换成」一个 error 事件。想想 `concatWith` 和 `onErrorResume` 谁在前谁在后，才能保证出错时不发 done

### 提示二：关键 API

| # | API |
|---|-----|
| 1 | `builder.defaultSystem(Resource)`、`@Value("classpath:prompts/system.st") Resource` |
| 2 | `instanceof TimeoutException / SocketTimeoutException / HttpTimeoutException`；Netty 的 `ReadTimeoutException` 不想引依赖可以按类名 `endsWith("TimeoutException")` 判断 |
| 3 | `chatClient.prompt().user(message).call().content()`，`ModelCallException.from(e)` |
| 4 | `chatClient.prompt().user(message).stream().content()`，`Flux#timeout(Duration)`，`Flux#onErrorMap` |
| 5 | `ProblemDetail.forStatusAndDetail`、`setTitle`、`setProperty("code", …)`，`HttpHeaders.RETRY_AFTER` |
| 6 | `ServerSentEvent.builder(data).event(name).build()`，`filter`（丢掉空片段）、`map`、`concatWith(Mono.fromSupplier(...))`、`onErrorResume(e -> Mono.just(...))` |

## 本地运行（Windows，不用 Docker）

1. 装 JDK 21（IDEA 里可以 File → Project Structure → SDK → Download JDK）
2. 从 <https://ollama.com/download> 下载 `OllamaSetup.exe` 安装，装完 Ollama 会常驻后台，监听 `http://localhost:11434`
3. PowerShell 里拉模型并试一句：
   ```powershell
   ollama pull qwen2.5:0.5b
   ollama run qwen2.5:0.5b "你好"
   ```
4. 启动应用（二选一）：
   - IDEA：打开项目，等 Maven 导入完成，运行配置选「智能客服（本地 Ollama）」点运行
   - 命令行：`.\mvnw.cmd spring-boot:run`
5. 浏览器打开 <http://localhost:8088/>，问一句「怎么申请退货？」，看回答是不是一个字一个字出来的；把 Ollama 退出（托盘图标 → Quit）再问一次，应当看到「智能客服暂时无法连接模型服务」的提示，调试面板里错误码为 `MODEL_UNAVAILABLE`

### 用远程 Ollama 或 OpenAI 兼容接口

不在本机跑模型时，把仓库根目录的 `application-local.example.yml` 复制为 `application-local.yml`（已被 git 忽略），填上远程 Ollama 的地址，或取消注释 `openai` 一段填 base-url / api-key / 模型名。IDEA 的两个运行配置都带了 `local` profile，会自动加载这个文件；命令行用 `.\mvnw.cmd spring-boot:run "-Dspring-boot.run.profiles=ollama,local"`（OpenAI 兼容接口换成 `openai,local`）。地址和密钥只写在这个本地文件里，不要写进 `src/main/resources` 或 `.run/` 运行配置。

## 想一想

- 0.5b 的小模型经常不听系统提示词的话（比如答非所问、说英文），换成 `qwen3:0.6b` 或更大的模型对比一下；第 2 章会用 Prompt 技巧和结构化输出改善这一点
- 阻塞接口的超时靠 HTTP 客户端的 `read-timeout`，流式接口靠 `Flux#timeout`，两者含义有什么不同？为什么 `spring.ai.retry.max-attempts` 要调小？
- SSE 的 data 为什么用 JSON 而不是纯文本（提示：看 `StreamEvents` 的注释）
